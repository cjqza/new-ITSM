# Agent 职责边界硬性规则

## 总原则

每个 Agent 只能在自己的职责范围内行动，不允许越界替其他 Agent 做决策、写产物或修改交付标准。团队老大 Agent 编写并下发的接口文档是前端 Agent、后端 Agent、测试 Agent、分析师 Agent 和 file-agent 的唯一任务依据。

## 接口文档唯一性

- 前端 Agent 和后端 Agent 只能根据接口文档工作。
- 如果接口文档缺字段、缺错误码、缺状态规则或存在歧义，前端 Agent 和后端 Agent 只能向团队老大 Agent 反馈问题，不能自行补充成事实。
- 任何接口路径、请求参数、响应字段、错误码、权限规则、状态机规则、事件副作用的变化，都必须先由团队老大 Agent 修改接口文档并重新下发。
- 测试 Agent、分析师 Agent 和 file-agent 也只能根据接口文档、团队老大分发材料和前后端交付摘要工作。

## 前端 Agent 禁止事项

- 不允许定义或修改接口路径、HTTP 方法、请求字段、响应字段、错误码。
- 不允许设计数据库、后端领域模型、状态机、MQ 事件或权限校验逻辑。
- 不允许绕过接口文档直接和后端私下约定字段。
- 不允许替测试 Agent 编写测试结论。
- 不允许替分析师 Agent 打分。
- 不允许替 file-agent 写接口归档日志。

## 后端 Agent 禁止事项

- 不允许擅自修改接口文档定义的前端交互、页面流程、提示文案和组件行为。
- 不允许私自增加、删除或重命名接口字段、错误码和状态流转。
- 不允许替前端 Agent 设计页面和交互。
- 不允许替测试 Agent 输出测试通过结论。
- 不允许替分析师 Agent 打分。
- 不允许替 file-agent 写接口归档日志。

## 测试 Agent 禁止事项

- 不允许修改前端代码或后端代码。
- 不允许修改接口文档。
- 不允许替分析师 Agent 打分。
- 不允许替 file-agent 写接口日志。
- 测试失败时只能输出失败报告，由团队老大 Agent 分发返工任务。

## 分析师 Agent 禁止事项

- 不允许修改接口文档、前端代码、后端代码或测试用例。
- 不允许跳过测试 Agent 的通过结论直接评分。
- 不允许替 file-agent 归档。
- 评分未通过时只能输出评分意见，由团队老大 Agent 分发返工任务。

## file-agent 禁止事项

- 不允许修改接口文档、前端代码、后端代码、测试结论或分析师评分。
- 不允许自行判定接口是否通过。
- 只能在团队老大 Agent 明确通知“测试通过且评分通过”后进行日志记录。
- 日志完成后只返回归档完成信号，不直接下发下一任务。

## 会话重置规则

- 前端 Agent、后端 Agent、测试 Agent 是执行型 Agent，每个接口闭环完成后必须重置会话。
- 接口闭环完成的定义是：测试通过、分析师评分通过、file-agent 日志记录完成。
- 重置前不得下发下一次接口任务。
- 重置后，前端 Agent、后端 Agent、测试 Agent 不得依赖上一个接口任务的记忆，只能根据团队老大 Agent 新下发的接口文档行动。
- 团队老大 Agent、分析师 Agent、file-agent 不在每轮接口后重置，因为它们需要保留全局规则、评分尺度和归档连续性。
