# ITSM 一期核心接口产品分析与功能分类 v1.0

> 分析视角：产品经理  
> 分析对象：`接口文档/ITSM一期核心接口文档_v1.0.md`  
> 分析日期：2026-08-25  
> 结论用途：指导一期研发排期、前后端分工和测试覆盖

## 1. 结论先行

一期接口文档的产品闭环是完整的，已经覆盖了“登录 - 聊天咨询 - Agent 首接 - 转人工 - 建单 - 客服处理 - 用户确认 - 用户评价 - 后台配置”这条主链路。

从产品视角看，这份接口文档可以分成 5 类核心功能域加 1 类内部编排能力：

1. 身份认证与权限门禁。
2. 用户会话与智能接待。
3. 工单创建与客服流转。
4. 用户评价与闭环反馈。
5. 字典与权限配置。
6. Agent 内部编排接口。

文档总计 25 个接口，其中 20 个属于一期主链路或必要支撑能力，5 个属于管理员配置能力。

## 2. 一期产品主链路

从用户体验看，一期要优先保证以下顺序：

1. 用户登录并获取权限。
2. 用户在“我的助手”中发起会话。
3. 用户发送消息，Agent 自动回答或自动触发转人工。
4. 系统自动创建工单并进入客服队列。
5. 客服受理工单，补齐分类、原因和解决方法。
6. 客服提交解决结果，用户确认。
7. 用户完成评价，形成闭环。

这个链路对应的是系统最核心的业务价值，也就是“聊天式接待 + 工单式处理”的统一体验。

## 3. 按功能域分类

### 3.1 身份认证与权限门禁

| 接口编号 | 接口名称 | 作用 | 主要角色 |
| --- | --- | --- | --- |
| `ITSM-AUTH-001` | 企业身份登录 | 交换企业 SSO 凭证，建立 ITSM 登录态 | 用户 / 客服 / 管理员 |
| `ITSM-AUTH-002` | 查询当前登录用户 | 刷新登录态、获取当前用户与租户信息 | 全部前端 |
| `ITSM-PERM-001` | 查询当前用户角色和权限 | 控制页面可见性和数据范围 | 全部前端 |

产品判断：

- 这一组是所有页面的入口，不只是登录页能力。
- `AUTH-001` 和 `PERM-001` 是“能不能进、能看到什么”的基础门禁。
- 权限前端可见性只做体验控制，真正权限仍以服务端校验为准。

### 3.2 用户会话与智能接待

| 接口编号 | 接口名称 | 作用 | 主要角色 |
| --- | --- | --- | --- |
| `ITSM-SESSION-001` | 创建会话 | 为聊天式咨询创建上下文容器 | 用户前端 |
| `ITSM-SESSION-002` | 读取会话 | 查看会话消息、摘要和关联工单 | 用户前端 / 客服详情页 |
| `ITSM-CHAT-001` | 发送用户消息 | 保存消息并触发 Agent 首轮接待 | 用户前端 |
| `ITSM-AGENT-001` | Agent 自助解决或转人工决策 | 内部编排，记录 Agent 结构化决策 | 内部服务 |
| `ITSM-AGENT-002` | 用户明确请求转人工 | 用户主动要求人工介入并转单 | 用户前端 |

产品判断：

- 这一组决定用户侧的交互体验是否像“聊天助手”，而不是传统表单工单。
- `CHAT-001` 是用户第一触点，必须保证消息先落库，再触发 Agent。
- `AGENT-002` 是重要兜底能力，保证用户不必等待模型判断就能转人工。
- `AGENT-001` 不面向前端，但它是一期必需的内部编排接口。

### 3.3 工单创建与客服流转

| 接口编号 | 接口名称 | 作用 | 主要角色 |
| --- | --- | --- | --- |
| `ITSM-TICKET-001` | 创建工单 | 用户手动建单或 Agent 转单建单 | 用户 / Agent |
| `ITSM-TICKET-002` | 工单分页查询 | 查询本人工单或权限范围内工单 | 用户 / 客服 / 管理员 |
| `ITSM-TICKET-003` | 工单详情查询 | 查看工单事实、分类、历史和评价 | 用户 / 客服 / 管理员 |
| `ITSM-SUPPORT-001` | 客服队列查询 | 查看待受理、处理中、待确认和历史工单 | 客服 / 管理员 |
| `ITSM-SUPPORT-002` | 客服受理工单 | 抢单或接单，成为当前处理人 | 客服 / 管理员 |
| `ITSM-SUPPORT-003` | 更新分类/原因/解决方法 | 补齐管理单元、症状、原因和解决方法 | 客服 / 管理员 |
| `ITSM-SUPPORT-004` | 提交工单解决结果 | 提交处理过程和解决说明 | 客服 / 管理员 |
| `ITSM-TICKET-004` | 用户确认解决 | 用户确认客服处理结果 | 用户 |
| `ITSM-SUPPORT-005` | 客服关闭工单 | 生命周期关闭，支持系统关闭任务 | 客服 / 系统 |
| `ITSM-TICKET-005` | 用户重开工单 | 用户对结果不满意时重新打开工单 | 用户 |

产品判断：

- 这一组是一期业务闭环的“骨架”，是最需要联调打通的部分。
- `TICKET-001` 是工单事实源，不能被前端伪造状态。
- `SUPPORT-001` 到 `SUPPORT-005` 对应客服台的核心动作，应该优先确保按钮状态、状态机和权限完全一致。
- `TICKET-004`、`TICKET-005` 和 `RATING-001` 共同构成用户闭环，决定用户是否能把服务处理结果真正收口。

### 3.4 用户评价与闭环反馈

| 接口编号 | 接口名称 | 作用 | 主要角色 |
| --- | --- | --- | --- |
| `ITSM-RATING-001` | 用户评价工单 | 收集满意度、标签和评论 | 用户 |

产品判断：

- 评价不是附属功能，而是闭环的最后一环。
- 没有评价，客服处理就很难形成可运营的结果数据。

### 3.5 字典与权限配置

| 接口编号 | 接口名称 | 作用 | 主要角色 |
| --- | --- | --- | --- |
| `ITSM-DICT-001` | 查询字典项 | 为客服分类和管理员配置页面提供数据 | 客服 / 管理员 |
| `ITSM-DICT-002` | 新增字典项 | 维护业务线、管理单元、症状、原因、解决方法 | 管理员 |
| `ITSM-DICT-003` | 更新字典项 | 修改字典名称、排序和父项 | 管理员 |
| `ITSM-DICT-004` | 停用字典项 | 控制哪些项还能用于新工单 | 管理员 |
| `ITSM-PERM-002` | 查询角色列表 | 查看当前租户可用角色 | 管理员 |
| `ITSM-PERM-003` | 查询角色权限 | 查看角色对应的权限集合 | 管理员 |

产品判断：

- 字典配置是客服分类标准化的关键，不是后台“可有可无”的维护项。
- `DICT-001` 是前台分类下拉的基础，`DICT-002/003/004` 是后台治理能力。
- `PERM-002/003` 目前只有查询，没有“新增角色 / 编辑权限 / 授权客服”的写接口，这一点和计划书里的“能给客服添加权限”存在落差。

## 4. 按角色分类

### 4.1 用户前端

用户前端主要涉及：

- `AUTH-001`、`AUTH-002`
- `PERM-001`
- `SESSION-001`、`SESSION-002`
- `CHAT-001`
- `AGENT-002`
- `TICKET-001`
- `TICKET-002`、`TICKET-003`
- `TICKET-004`、`TICKET-005`
- `RATING-001`

用户前端的核心目标只有一个：让用户能顺畅地把问题说清楚，并且看到处理结果和评价入口。

### 4.2 客服前端

客服前端主要涉及：

- `AUTH-001`、`AUTH-002`
- `PERM-001`
- `TICKET-002`、`TICKET-003`
- `SUPPORT-001`、`SUPPORT-002`、`SUPPORT-003`、`SUPPORT-004`、`SUPPORT-005`
- `DICT-001`

客服前端的核心目标是：快速受理、快速分类、快速解决、快速关闭。

### 4.3 管理员前端

管理员前端主要涉及：

- `AUTH-001`、`AUTH-002`
- `PERM-001`
- `PERM-002`、`PERM-003`
- `DICT-001`、`DICT-002`、`DICT-003`、`DICT-004`
- `TICKET-002`、`TICKET-003`
- `SUPPORT-001` 到 `SUPPORT-005`

管理员前端的核心目标是把分类标准、角色权限和业务字典稳定下来。

### 4.4 内部服务

内部服务主要涉及：

- `ITSM-AGENT-001`
- `ITSM-TICKET-001` 的 `AGENT_SERVICE` 调用方式

这一层不是前端页面能力，而是系统编排和事实写入能力。

## 5. 一期优先级建议

### 5.1 P0，必须一期交付

| 功能域 | 接口 |
| --- | --- |
| 登录与权限 | `AUTH-001`、`AUTH-002`、`PERM-001` |
| 会话与聊天 | `SESSION-001`、`SESSION-002`、`CHAT-001`、`AGENT-002` |
| 工单主链路 | `TICKET-001`、`TICKET-002`、`TICKET-003` |

| 内部编排 | `AGENT-001` |

| 功能域 | 接口 |
| --- | --- |
| 字典治理 | `DICT-002`、`DICT-003`、`DICT-004` |
| 角色查询 | `PERM-002`、`PERM-003` |

## 6. 产品视角的风险与建议

1. 权限管理能力不完整。当前接口只有“查角色”和“查角色权限”，没有“给客服授权、改角色、编辑权限”的写接口。如果一期真的要支持“管理员给客服添加权限”，需要补充对应接口。
2. Agent 内部接口必须和前端接口严格隔离。`AGENT-001` 不能让用户或客服直接调用，否则会破坏工单事实源。
3. 字典治理要与工单状态机绑定。字典项停用后，历史工单仍要能展示旧值，但新工单不能再选。
4. 附件上传被刻意放在接口之外，只接 `fileId`。这意味着前端联调时要先有统一文件服务，否则聊天和工单附件会卡住。
5. 客服处理链路要强校验状态机。受理、分类、解决、关闭、重开都不能靠前端按钮状态“猜”。

## 7. 产品结论

这份一期接口文档的产品结构是合理的，已经不是“零散接口清单”，而是一条可闭环的 ITSM 服务链路。

如果按上线节奏推进，建议把一期目标定义为：

“用户能在聊天式工作台完成咨询和转人工，客服能在工单台完成受理、分类、解决和关闭，管理员能维护分类字典和权限查询，最终用户能评价并重新打开问题。”

这就是一期最值得优先打通的主价值。
