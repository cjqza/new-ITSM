# 第3轮接口文档 v3.0：技术支持、解决、用户确认、评价与重开

## 1. 团队老大结论

第 3 轮补齐人工处理链路后半段：客服进入技术支持、提交解决方案，用户确认解决、评价，客服关闭，用户可重开未解决工单。Java 继续负责工单事实和状态机，Python Agent 不参与状态修改。

## 2. 接口清单

| 接口编号 | 接口名称 | 方法 | 路径 |
|---|---|---|---|
| ITSM-R3-001 | 客服进入技术支持 | POST | `/api/v1/support/tickets/{ticketId}/support` |
| ITSM-R3-002 | 客服提交解决方案 | POST | `/api/v1/support/tickets/{ticketId}/resolve` |
| ITSM-R3-003 | 用户确认解决 | POST | `/api/v1/user/tickets/{ticketId}/confirm` |
| ITSM-R3-004 | 用户评价工单 | POST | `/api/v1/user/tickets/{ticketId}/evaluations` |
| ITSM-R3-005 | 客服关闭工单 | POST | `/api/v1/support/tickets/{ticketId}/close` |
| ITSM-R3-006 | 用户重开工单 | POST | `/api/v1/user/tickets/{ticketId}/reopen` |

## 3. 状态机规则

- 技术支持：`TECH_ANALYSIS` -> `IN_SUPPORT`。
- 提交解决方案：`ACCEPTED`、`TECH_ANALYSIS`、`IN_SUPPORT` -> `PENDING_USER_CONFIRM`。
- 用户确认解决：`AGENT_ANSWERED` 或 `PENDING_USER_CONFIRM` -> `RESOLVED`。
- 用户评价：仅允许 `RESOLVED` 或 `CLOSED`。
- 客服关闭：`RESOLVED` -> `CLOSED`。
- 用户重开：`PENDING_USER_CONFIRM`、`RESOLVED`、`CLOSED` -> `REOPENED`。

## 4. 前端 Agent 任务

- 设计技术支持记录、解决方案提交、用户确认、评价和重开入口。
- 严格按状态机控制按钮可见性。

## 5. 后端 Agent 任务

- 实现技术支持、解决、确认、评价、关闭、重开接口。
- 所有状态变更必须写入状态历史和审计事件。
- 评分字段必须限制在 1 到 5 分。

## 6. 测试 Agent 必测场景

- 完整人工链路：转人工 -> 受理 -> 分析 -> 技术支持 -> 解决 -> 用户确认 -> 评价。
- 未进入技术分析不能直接进入技术支持。
- 未解决工单不能评价。
- 评分越界返回 `VALIDATION_ERROR`。
- 已解决工单可关闭，关闭后可重开。

## 7. 验收标准

- 第 3 轮接口均已在 Java Controller 和 Service 中落地。
- 测试覆盖完整人工闭环和非法状态。
- 分析师评分大于等于 85。
