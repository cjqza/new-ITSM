# ITSM UI 信息架构与原型说明 v0.1

版本：v0.1  
日期：2026-08-25  
适用范围：用户侧、客服侧、管理员侧  
文档性质：接口文档下发前的 UI 需求梳理与原型草案

## 1. 文档定位与边界

本文档依据：

- `计划书/ITSM桌面工单处理系统计划书.md`
- `.agents/agent-boundary-rules.md`
- 三张参考截图：个人工作台、服务请求列表、配置页

本文档只描述：

- 页面层级、导航关系和信息架构
- 页面区块、组件和视觉布局
- 用户操作意图、交互反馈和页面状态
- 不同角色看到的页面差异
- 桌面优先下的响应式策略
- 接口文档完成后需要补齐的 UI 对接点

本文档明确不定义：

- 接口路径、HTTP 方法、请求字段、响应字段
- 错误码、后端数据对象字段和数据库结构
- 工单状态机、状态转换条件和事件副作用
- 权限校验逻辑、数据权限判定规则和后端角色编码
- 任何可以被误读为接口契约的字段命名

本文中的“工单”“服务请求”“业务系统”“字典”“角色”等词，只表示界面概念。最终展示值、按钮可见性、可编辑性、操作结果和异常提示，必须以团队主 Agent 后续下发的接口文档为准。

## 2. 设计目标

### 2.1 用户侧目标

让用户以聊天的方式完成以下连续体验：

1. 进入“我的助手”。
2. 描述问题或提出咨询。
3. 阅读智能客服的回答、建议或追问。
4. 在需要人工处理时，清楚知道已经进入服务请求处理过程。
5. 回看处理进度、补充上下文、确认结果并完成评价。

### 2.2 客服侧目标

让客服在一个高密度、可扫描的工作台中快速完成：

1. 找到需要自己关注的服务请求。
2. 先看标题、业务线、提交人、时间、处理归属等摘要信息。
3. 进入详情后查看聊天上下文、问题摘要和历史动作。
4. 按页面引导补齐分类、原因和解决方法等业务信息。
5. 记录处理过程，提交处理结果，并在允许时继续跟进。

### 2.3 管理员侧目标

让管理员能够在保持数据密度的同时，维护：

- 业务系统与业务线相关配置
- 管理单元、症状、原因、解决方法等字典
- 角色、菜单、按钮和数据范围等权限配置
- 配置与权限变更的可追溯入口

## 3. 总体信息架构

### 3.1 一级导航

参考截图采用固定左侧一级导航。建议保留以下逻辑分组：

| 一级入口 | 面向角色 | 页面职责 | 备注 |
| --- | --- | --- | --- |
| 首页 / 工作台 | 用户、客服、主管 | 进入当前角色的工作概览 | 用户侧可聚焦“我的助手”，客服侧可聚焦待处理概览 |
| 工单 / 服务请求 | 客服、主管 | 浏览、筛选和处理服务请求 | 普通客服默认进入自己可处理的范围 |
| 配置 | 管理员 | 业务系统、字典、分流及权限维护 | 非管理员不显示或不可进入 |
| 监视 / 运营 | 主管、质检（可选） | 后续统计、抽检和运营观察 | 一期可以保留占位，不承诺具体指标 |

用户侧不需要展示客服管理菜单。普通客服不需要展示管理员配置菜单。导航显示只代表 UI 可见性，不代表权限逻辑已经在本文中定义。

### 3.2 全局壳层

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶部栏：面包屑 / 全屏 / 当前用户 / 更多操作                        │
├───────┬────────────────────────────────────────────────────────────┤
│       │ 页签栏：个人工作台、服务请求、业务系统、症状、原因...       │
│ 左侧  ├────────────────────────────────────────────────────────────┤
│ 导航  │ 页面标题区 / 页面工具栏                                     │
│       ├────────────────────────────────────────────────────────────┤
│       │ 内容区：面板、列表、详情、表单、对话                        │
└───────┴────────────────────────────────────────────────────────────┘
```

全局壳层建议包含：

- 左侧固定导航：图标 + 中文标签，当前项使用深色选中块或蓝色强调。
- 顶部面包屑：展示当前模块层级，长标题需要截断并支持悬浮查看。
- 页签栏：支持多个工作页并行打开，当前页签使用蓝色文字和底部线条。
- 当前用户区：头像、姓名、下拉菜单；菜单内容由接口文档和权限配置确定。
- 内容工作区：浅灰背景，内部使用白色面板承载主要内容。
- 全局刷新或更多操作：使用图标按钮，提供明确 tooltip。

### 3.3 页面级信息层级

所有主页面遵循以下顺序：

1. 页面标题与当前上下文。
2. 页面级操作和筛选。
3. 核心内容区。
4. 次级信息、历史或审计信息。
5. 操作反馈、空状态和异常恢复入口。

页面不使用大面积营销式 Banner。ITSM 页面优先保证可扫描、可比较和连续处理。

## 4. 参考截图的布局规律

### 4.1 截图一：个人工作台

截图一呈现出典型的客服首页布局：

- 左侧是固定导航，宽度稳定，视觉上与内容区形成明确分隔。
- 顶部有面包屑和页签，工作台与服务请求可以并行打开。
- 主体使用左右两列布局。
- 左侧上方为草稿箱，下方为即将超时的服务请求。
- 右侧上方为“等待我处理的服务请求”，下方为“待本岗位处理的服务请求”。
- 每个区块都有区块标题、数量或分类页签。
- 行内信息采用紧凑排列，标题是第一视觉重点，人员、邮箱、组织、服务台等是辅助信息。
- 关键操作使用蓝色按钮，例如“受理”；时间、比例、优先级等使用彩色标签或轻量徽标。
- 面板之间保留清晰间距，区块内部以分割线区分记录。

对本项目的启示：

- 客服首页应优先展示“我需要处理什么”，而不是只展示统计数字。
- 需要支持从摘要行直接进入详情或执行高频动作。
- 视图数量较多时，应使用页签和数字徽标区分，不应将所有条件堆到一个复杂筛选条中。

### 4.2 截图二：服务请求列表

截图二呈现出高密度工单列表：

- 顶部是页面标题、主操作、批量操作入口、分页和搜索。
- 表格列较多，标题列占主要宽度。
- 左侧有颜色区块或百分比提示，用于强调时效、进度或风险类信息。
- 标题通常使用蓝色可点击文本，并可带业务标签、人员标签或其他辅助徽标。
- 表格行使用细分割线，信息密度高但仍保持清晰。
- 重要字段集中在固定列，时间和版本信息靠右排列。
- 表格支持横向滚动的可能性较高，因此要保证标题列和选择列的可用性。
- “新增”“操作”“导出”等位于工具栏，分页位于工具栏右侧或同一行。

对本项目的启示：

- 客服列表需要先支持快速扫描，再支持详情深入。
- 工单标题应允许多行，但要设置最大行数和展开方式，避免一条长文本撑坏整表。
- 表格中的动作应该根据当前角色和接口文档返回的可操作性展示，不能由前端自行推断。
- 过滤条件可以分为常用筛选和组合查询，避免默认展开过多输入项。

### 4.3 截图三：配置页

截图三呈现出配置管理页面：

- 顶部面包屑显示“配置 > 管理单元 > 业务系统”。
- 页签栏承载“业务系统、症状、原因、解决办法”等并列配置入口。
- 页面标题左侧显示总数、分页大小和页码。
- 中间区域是搜索框与搜索标签。
- 右侧提供组合查询、目录修正、导出、应用最新配置、自定义等工具。
- 主体是表格，当前截图为无数据状态。
- 无数据图位于表格主体中央，文案简短，留白较多。

对本项目的启示：

- 配置模块适合使用统一列表模板，切换不同字典类型时保持工具栏和表格结构稳定。
- 字典类数据需要支持层级浏览或树形目录，但是否以树形展示、是否支持批量操作需待接口文档和需求确认。
- 空状态必须保留页面上下文和可用操作，不能只显示一块无数据图片。

## 5. 用户聊天式工作台

### 5.1 页面定位

用户侧默认入口为“我的助手”。页面以聊天为主，辅以服务请求上下文和历史入口。目标是让用户在不理解工单概念的情况下，也能完成咨询、转人工、追踪和评价。

### 5.2 页面结构

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶部：我的助手 / 当前会话标题 / 更多                           │
├───────────────────────┬─────────────────────────────────────┤
│ 会话列表               │ 对话区                               │
│ - 最近会话             │ 头部：助手名称、当前服务上下文         │
│ - 进行中的服务请求     │ 消息流：用户消息、助手消息、系统提示    │
│ - 历史记录             │ 快捷建议 / 引导卡片                    │
│                       │ 底部：输入框、附件、发送、转人工入口      │
├───────────────────────┴─────────────────────────────────────┤
│ 可选：当前服务请求摘要 / 进度 / 评价入口                         │
└─────────────────────────────────────────────────────────────┘
```

建议在桌面端使用三栏可选布局：

- 左栏：会话和服务请求入口。
- 中栏：聊天主区。
- 右栏：当前服务请求摘要或帮助信息。

首次实现可以使用“两栏布局 + 可收起右侧摘要”，以保证聊天区宽度。右栏是否默认展开可以通过界面配置调整，不绑定接口字段。

### 5.3 核心区块与组件

| 区块 | 组件 | 交互草案 |
| --- | --- | --- |
| 会话导航 | 会话项、搜索、未读提示 | 点击切换会话；新消息用轻量提示，不强制打断输入 |
| 对话头部 | 助手头像、名称、会话更多菜单 | 可查看帮助、清空当前视图或退出当前会话；具体动作待接口文档确认 |
| 消息流 | 气泡、时间分隔、引用卡片、附件卡片 | 支持长文本、代码或步骤列表的可读展示；消息加载中显示骨架或动态占位 |
| 建议区 | 快捷问题、推荐操作、追问选项 | 点击后作为用户意图输入；不能把快捷项当成固定后端枚举 |
| 人工转接 | 文本按钮或图标+文本按钮 | 用户明确请求人工时进入转接确认态；是否立即建单、是否排队待接口文档确认 |
| 输入区 | 多行输入框、附件入口、发送按钮 | Enter 发送、Shift+Enter 换行；发送中禁用重复提交 |
| 服务请求摘要 | 标题、当前阶段展示、最近更新时间、进入详情 | 仅展示接口文档允许展示的摘要信息，阶段名称和可执行按钮由接口契约决定 |
| 评价入口 | 评分、标签、补充说明 | 仅在服务请求允许评价时出现；提交后展示结果反馈 |

### 5.4 用户主流程草案

#### A. 自助咨询

1. 用户打开“我的助手”，看到欢迎语和常用问题建议。
2. 用户输入问题并发送。
3. 消息流展示助手的处理占位，再展示回答或追问。
4. 用户可以继续追问、点击建议项或重新描述。
5. 若用户认为问题已解决，可结束当前对话或回到工作台。

这里不预设后端如何判断“已解决”，也不规定任何状态转换。页面只负责呈现服务端返回的可用操作和提示。

#### B. 转人工或生成服务请求

1. 用户点击“转人工”或在对话中明确表达需要人工。
2. 页面弹出轻量确认区域，说明将把当前上下文交给人工服务。
3. 用户确认后，页面展示提交中、排队中或已转交等服务反馈。
4. 页面保留聊天上下文，并在摘要区提供进入服务请求详情的入口。
5. 后续客服消息通过会话区进入，用户可以继续补充信息。

“提交中”“排队中”等仅是 UI 反馈阶段，不表示本文定义了后端状态机。

#### C. 查看处理进度与评价

1. 用户在会话列表或工作台摘要中打开服务请求。
2. 页面展示可见的处理进度、最近处理记录和客服回复。
3. 在服务端允许评价时显示评价控件。
4. 评价完成后显示提交结果，并保留补充说明或追问入口（具体是否保留由接口文档确定）。

### 5.5 聊天页面状态

| 状态 | 页面表现 | 用户可做的事 |
| --- | --- | --- |
| 首次进入 | 欢迎语、建议问题、空会话占位 | 输入问题、点击建议 |
| 正在加载 | 消息骨架、输入区保持稳定 | 可等待；避免重复发送 |
| 消息发送失败 | 消息旁显示失败标记和重试 | 重试或编辑后重新发送 |
| 助手暂不可用 | 对话区给出简短说明，保留人工入口（若服务端返回可用） | 重试、转人工或离开 |
| 会话无记录 | 空状态与“开始咨询”入口 | 发起新问题 |
| 网络中断 | 顶部轻量告警，不遮挡已读内容 | 恢复后重试 |
| 服务请求不存在或不可见 | 不泄漏详情，显示不可查看提示 | 返回工作台 |
| 无权限 | 不展示受限内容，显示返回入口 | 返回可访问页面 |
| 评价提交中 | 评价控件锁定并显示处理中 | 等待结果 |
| 评价失败 | 保留已填内容，提供重试 | 重试或取消 |

## 6. 客服工作台

客服侧分为“工作台首页”“服务请求列表”“服务请求详情”三类核心页面。三者通过页签、面包屑和列表行跳转连接。

### 6.1 客服工作台首页

#### 6.1.1 页面结构

参考截图一，建议采用可调比例的两列面板：

```text
┌───────────────────────────────────────────────────────────────────┐
│ 页面标题：个人工作台    [新建/快捷入口]                 [设置]      │
├───────────────────────────────┬───────────────────────────────────┤
│ 草稿箱                        │ 等待我处理的服务请求               │
│  ┌───────────────────────────┐ │  ┌─────────────────────────────┐  │
│  │ 分类页签 + 数量            │ │  │ 分类页签 + 数量              │  │
│  │ 服务请求摘要列表           │ │  │ 服务请求摘要列表             │  │
│  └───────────────────────────┘ │  └─────────────────────────────┘  │
│                               │                                   │
│ 即将超时的服务请求              │ 待本岗位处理的服务请求             │
│  ┌───────────────────────────┐ │  ┌─────────────────────────────┐  │
│  │ 分类页签 + 数量            │ │  │ 分类页签 + 数量              │  │
│  │ 服务请求摘要列表           │ │  │ 服务请求摘要列表             │  │
│  └───────────────────────────┘ │  └─────────────────────────────┘  │
└───────────────────────────────┴───────────────────────────────────┘
```

#### 6.1.2 面板内容

- 草稿箱：展示尚未完成或待继续处理的内容，使用标题、提交人、时间和继续处理入口。
- 等待我处理：展示当前客服需要优先关注的服务请求，突出风险、等待时长和受理入口。
- 即将超时：突出时间风险，颜色只用于风险提示，不作为唯一识别方式。
- 待本岗位处理：展示岗位或业务线范围内可处理的服务请求。

面板名称可依据最终产品词汇调整。面板中的“数量”只作为服务端聚合结果的展示，不在本文定义统计口径。

#### 6.1.3 摘要行设计

每条摘要行建议分为三层：

1. 第一行：颜色提示、业务标签、服务请求标题或编号。
2. 第二行：提交人、联系方式、组织/部门、业务归属等辅助信息。
3. 右侧：时间、进度或高频动作。

桌面端行高应允许两行摘要信息；标题较长时最多显示两行并截断，点击整行进入详情。

#### 6.1.4 交互

- 点击面板页签只切换面板内视图，不离开工作台。
- 点击摘要行进入服务请求详情。
- 点击“受理”等动作前，显示轻量确认或直接进入处理中反馈，具体行为等待接口文档。
- 面板支持刷新，刷新时不清空已有内容，使用局部骨架或遮罩。
- 面板无数据时显示区块内空状态，而不是让整页出现单一空状态。
- 通过“查看更多”进入带筛选条件的服务请求列表；筛选条件是否能够回填，以接口文档允许的查询能力为准。

### 6.2 服务请求列表页

#### 6.2.1 页面结构

```text
┌───────────────────────────────────────────────────────────────────┐
│ 标题：服务请求       [新增] [操作▼]       分页 / 搜索 / 导出        │
├───────────────────────────────────────────────────────────────────┤
│ 常用筛选：视图页签 / 轻量筛选 / 高级筛选折叠                       │
├───────────────────────────────────────────────────────────────────┤
│ 选择 | 风险/进度 | 编号 | 标题 | 业务系统 | 阶段 | 提交人 | 归属... │
│ ───────────────────────────────────────────────────────────────── │
│      |          |      |      |          |      |        |         │
│      |          |      |      |          |      |        |         │
└───────────────────────────────────────────────────────────────────┘
```

#### 6.2.2 工具栏

- 页面标题与当前视图名称。
- 新增或创建入口：只在服务端允许且角色可见时显示。
- 操作菜单：承载批量动作，按钮名称和可用动作由接口文档决定。
- 分页器：当前页、页码、每页条数和总数展示。
- 搜索框：提供工单号、用户或标题等概念上的搜索入口；具体可搜字段以后端接口文档为准。
- 导出：保留为工具栏能力，导出范围和权限不在本文定义。
- 高级筛选：适用于业务线、时间、处理归属和阶段等维度；默认折叠，避免挤压列表空间。

#### 6.2.3 表格列建议

以下是 UI 概念列，不是接口字段定义：

| 列 | 展示重点 | 交互 |

#### 6.2.4 列表交互

- 点击标题或编号进入详情页。
- 点击表头排序只在接口文档明确支持时启用。
- 选择行后显示批量操作工具条；若无可用批量动作，保持隐藏。
- 切换视图后保留当前搜索关键词，但是否保留高级筛选需由产品确认。
- 列宽可调，标题列设置最小宽度，避免辅助列挤压标题。
- 表格支持横向滚动；左侧选择列和编号列可按实现条件固定。
- 大量数据时优先使用分页；虚拟滚动是否采用待实现方案评估。

#### 6.2.5 列表状态

| 状态 | 页面表现 |
| --- | --- |
| 首次加载 | 表头立即显示，表格行显示骨架，工具栏保持可见 |
| 有数据 | 正常显示分页、筛选和行级动作 |
| 无数据 | 表格区域居中显示空状态，说明当前视图没有可显示记录，并保留清空筛选或返回入口 |

| 会话失效 | 由全局认证机制处理，页面保留返回或重新进入入口 |

### 6.3 服务请求详情页

#### 6.3.1 页面目标

详情页是客服实际处理的主工作区，需要同时满足：

- 快速理解用户问题。
- 快速回看聊天上下文。
- 看到当前服务请求的摘要和处理记录。
- 完成分类、排查、记录和结果提交。
- 在不丢失上下文的情况下返回列表。

#### 6.3.2 页面结构

建议采用“左摘要 + 中内容 + 右处理”的三栏布局：

- 中栏最宽，承担聊天记录、描述和附件阅读。
- 右栏固定或半固定，承担分类、处理和动作。

窄屏时切换为顶部摘要 + 分段页签或抽屉，不要求三栏同时挤在一个视口中。

#### 6.3.3 详情区块

**请求摘要**

- 标题、编号、业务归属、提交人和关键时间。
- 风险或时效提示。
- 当前服务端允许展示的阶段提示。
- 复制编号、打开关联会话等辅助动作。

**聊天上下文**

- 按时间展示用户、智能客服和人工客服消息。
- 允许折叠冗长系统消息。
- 对长文本、代码、附件和链接做安全的阅读型展示。
- 提供“查看完整会话”或“定位到首次提问”的导航意图。

**处理信息**

- 业务系统或业务线选择。
- 管理单元、症状、原因、解决方法等分类控件。
- 自定义补充说明。
- 内部备注与对用户可见回复应在视觉上明确区分。
- 所有必填性、选项来源和可编辑性以后续接口文档为准。

**处理时间线**

- 以时间线呈现关键动作和处理记录。
- 操作者、时间、动作摘要和备注是界面概念。
- 不在本文规定动作类型、事件顺序或后端审计字段。

**底部动作区**

- 固定在右侧处理栏底部或详情页底部。
- 主动作使用蓝色按钮，次要动作使用次级按钮，危险动作使用危险色并二次确认。
- 动作按钮名称和可见条件由接口文档决定。
- 提交过程中禁用重复提交，失败时保留用户输入。

#### 6.3.4 详情页交互

- 从列表进入详情后，保留来源视图和返回位置。
- 详情加载期间先呈现页面骨架，避免整页白屏。
- 切换分类项时只更新相应局部控件，避免清空已填写的处理记录。
- 离开有未保存编辑的页面时弹出离开确认。
- 操作成功后，在按钮附近给出短反馈，并刷新受影响的区块。
- 如果服务端返回内容发生变化，页面显示轻量更新提示，允许用户刷新当前详情。
- 任何页面动作的最终可用性、可见性、顺序和副作用以后续接口文档为准。

## 8. 页面通用状态与反馈规范

### 8.1 空状态

空状态应包含：

- 简洁图形或轻量图标。
- 明确说明当前页面或当前筛选范围没有内容。
- 一个最相关的下一步入口，例如开始咨询、清空筛选、创建配置。

不要在空状态中使用接口字段名、内部错误文本或无法理解的编码。

### 8.2 加载状态

- 页面首次加载使用骨架屏，保持表头、工具栏和主要区块尺寸稳定。
- 局部刷新只遮罩受影响区块，保留用户正在阅读的其他内容。
- 提交动作使用按钮内加载，不让用户误以为页面失去响应。
- 聊天消息加载不能让输入框上下跳动。

### 8.3 失败状态

失败提示应说明：

- 哪个区块无法加载或提交。
- 用户可以采取的动作：重试、返回、清空输入或联系管理员。
- 可恢复操作使用蓝色主按钮；不可恢复或无权访问不要提供误导性的重试。

错误码和错误分类不得由本 UI 文档自行定义。前端接入时只消费接口文档规定的错误表达。

### 8.4 无权限状态

- 页面级无权限：显示标题、无权访问说明和返回入口。
- 区块级无权限：保留区块标题，内容区显示不可查看占位。
- 操作级无权限：隐藏操作或显示不可用状态，具体策略以接口文档为准。
- 不通过前端隐藏文本来推断用户是否有权限，避免把受限数据泄露到 DOM 或提示中。

### 8.5 成功反馈

- 列表操作成功：局部刷新当前行或列表，并给出短暂提示。
- 表单保存成功：关闭抽屉或转为只读预览，具体行为待确认。
- 详情动作成功：更新相关摘要、时间线和动作区。
- 评价成功：保留评价结果的只读显示，避免重复提交。

## 9. 响应式策略

### 9.1 设计优先级

本项目参考截图明显面向桌面端，因此采用桌面优先，但要避免只在宽屏可用：

1. 宽桌面：完整左侧导航、页签、多栏详情和高密度表格。
2. 普通桌面或小笔记本：左侧导航可收窄，详情三栏允许折叠或切换。
3. 平板宽度：侧边栏转为抽屉，表格减少次要列，详情使用分段页签。
4. 手机宽度：聊天工作台保留完整主流程；客服列表改为卡片摘要；配置表单改为单栏。

### 9.2 断点行为

不在本文锁定具体像素断点，实施时根据现有前端框架和设计系统确定。行为要求如下：

- 导航收窄时保留图标，并提供 tooltip 或展开入口。
- 页签过多时支持横向滚动或溢出菜单。
- 工具栏在窄屏下分行，主操作优先保留。
- 表格不强制所有列缩小到不可读，允许横向滚动或切换为摘要卡片。
- 客服详情页从三栏切换为“摘要 / 对话 / 处理”分段视图。
- 聊天输入框固定在可视区域底部，键盘出现时不能遮挡发送按钮。
- 所有标签、按钮和提示文本允许换行，不能因中文长文本溢出或覆盖其他内容。

### 9.3 可访问性与可读性

- 颜色标签必须配合文字、图标或 tooltip。
- 主要按钮具备键盘焦点状态。
- 表格表头、行内容和操作按钮具备清晰的阅读顺序。
- 长标题、长组织名、长处理方法需要截断、换行和全文查看机制。
- 危险操作使用明确文案和确认，不只使用红色图标。

视觉建议：

- 主色：参考截图中的明亮蓝，用于选中态、链接和主操作。
- 导航：深蓝灰色，保持稳定的工作台识别。
- 工作区：浅灰背景，内容面板使用白色。
- 辅助状态：绿色表示正向或低风险，黄色表示需要关注，红色表示危险或失败；所有颜色都配合文字。
- 边框：细浅灰分隔，面板圆角保持克制，避免卡片套卡片。
- 字体：中文优先使用系统无衬线字体；标题、正文、辅助信息建立清晰层级。
- 密度：客服列表和配置列表偏紧凑，聊天消息和详情说明保留更舒适的行高。

## 11. 接口文档下发后的 UI 对接清单

接口文档完成后，团队主 Agent 下发给前端 Agent 时，需逐项补充以下内容：

- 每个页面的真实数据来源和加载时机。
- 列表、详情、会话、配置和权限的接口边界。
- 页面动作与接口动作的对应关系。
- 每个动作成功后需要刷新的区块。
- 可展示的字段、字段为空时的展示策略和脱敏要求。
- 错误码到用户提示的映射。
- 工单阶段展示名称和允许操作集合。
- 角色、菜单、按钮和数据范围的可见性规则。
- 分页、排序、搜索、组合筛选和导出能力。
- 消息实时更新或轮询策略。
- 并发编辑、重复提交和数据版本冲突处理方式。

在上述内容确认前，原型可以使用静态占位数据进行视觉和交互评审，但不得接入或模拟未经下发的真实接口契约。

## 12. 待团队主 Agent 确认的问题

以下问题会影响最终原型，但本文不自行给出答案：

1. 用户工作台是否允许用户直接新建服务请求，还是只能从聊天转人工。
2. 聊天式工作台是否需要保留多个历史会话，以及历史会话的可见范围。
3. 客服首页各面板的排序、数量口径和默认筛选。
4. 服务请求详情是否允许客服直接改派、转交或撤回。
5. 分类、原因和解决方法是否全部必填，是否允许自定义文本。
6. 管理员配置中的业务系统、业务线和分流规则如何组织。
7. 权限页面采用菜单树、按钮清单还是两者组合。
8. 用户侧、客服侧和管理员侧是否共享同一套顶部页签。
9. 评价入口出现的条件、评价完成后的可见范围和是否支持追评。
10. 实时消息、刷新频率和离线恢复体验由哪份接口或事件文档约束。

## 13. 交付说明

本版本可用于：

- 产品、设计和开发的页面范围评审。
- 后续接口文档编写时核对页面所需能力。
- 前端在接口下发前制作不绑定字段的静态视觉草案。

本版本不可用于：

- 直接生成后端接口。
- 直接实现数据库或权限校验。
- 推导工单状态转换、错误码和数据字段。
- 作为未经过团队主 Agent 下发的前后端联调契约。
