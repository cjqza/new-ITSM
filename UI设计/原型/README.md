# ITSM 一期静态 UI 原型

这是一个零依赖、可直接打开的静态 UI 原型。入口文件是同目录下的 `index.html`，不需要安装 npm、不需要启动服务，也不会调用真实后端接口。

## 打开方式

直接双击打开 `index.html`，或在浏览器中选择“打开文件”。由于 CSS、JS 和 mock 数据都内嵌在单个 HTML 文件中，使用 `file://` 打开即可运行。

## 页面范围

原型提供三个可切换视图：

1. **我的助手**
   - 会话列表与会话切换
   - 聊天消息区、快捷问题、发送
   - 转人工入口
   - 关联工单摘要、状态和进度
   - `PENDING_USER_CONFIRM` 工单确认/重开
   - `RESOLVED` / `CLOSED` 工单评价入口，评分限制为 1-5

2. **客服工单**
   - 个人工作台四个队列面板
   - 待受理、处理中、待确认、历史视图
   - 关键词筛选和本地分页占位
   - 高密度工单表格、横向滚动
   - 受理工单
   - 工单详情抽屉
   - 分类保存、提交解决、关闭工单

3. **管理员配置**
   - 业务系统、管理单元、症状、原因、解决方法页签
   - 编码/名称搜索
   - 字典项列表和空状态
   - 新增字典项弹窗
   - 停用字典项确认弹窗

## Mock 边界

- 所有数据都写在 `index.html` 内的 `mock` 对象中，刷新页面会恢复初始数据。
- 所有按钮只修改浏览器当前页面内存，不产生持久化数据。
- 没有 `fetch`、XHR、WebSocket、npm 包或真实接口请求。
- 页面上的 `Mock` 标识用于明确说明当前是视觉和交互演示。
- 原型没有新增接口路径或字段；展示的状态、角色、字段名、动作名和错误码来自：
  - `接口文档/ITSM一期核心接口文档_v1.0.md`
  - `UI设计/UI信息架构与原型说明_v0.1.md`
- 主要状态使用正式接口枚举：`PENDING_ACCEPTANCE`、`IN_PROGRESS`、`PENDING_USER_CONFIRM`、`RESOLVED`、`CLOSED`、`REOPENED`。
- 交互反馈使用正式错误码示例：`SUCCESS`、`VALIDATION_ERROR`、`RESOURCE_CONFLICT`、`ILLEGAL_STATE_TRANSITION`。
- 不代表当前已经具备认证、租户隔离、角色校验、幂等、并发控制、审计、领域事件或真实工单持久化能力。

## 响应式说明

原型桌面优先；窗口变窄时：

- 左侧导航保持可用并收窄。
- 聊天工作台从三列调整为两列或单列。
- 客服表格保留最小可读宽度并允许横向滚动。
- 工单详情从右侧抽屉全屏化。
- 配置页工具栏允许换行。
